# Architecture import fixtures

Sample files for the guided architecture import (Catalog → **Import from Excel
or CSV**) and the script that verifies the whole flow end to end.

| File | Purpose |
|---|---|
| `systems.csv` | Four system rows: create, match by external ID, update, and skip |
| `systems.xlsx` | The same systems as a real workbook (generated by `make-sample-xlsx.mjs`) |
| `information-objects.csv` | Information objects, including one authoritative system resolved by alias and one unresolved row |
| `integrations.csv` | Contracts with resolvable endpoints, an existing-contract update, and an unresolved endpoint |
| `solutions.csv` | A solution over existing systems plus one with an unresolved member |
| `make-sample-xlsx.mjs` | Regenerates `systems.xlsx` from `systems.csv` (`node fixtures/architecture-import/make-sample-xlsx.mjs`) |
| `verify_import_flow.py` | Runs the twelve verification steps against a live API |

## Running the verification

The script logs in as a dedicated verification user in its own workspace so the
demo data is never touched. Create that user once (a local development database
only), for example:

```sh
cd api
HASH=$(.venv/bin/python -c "from app.auth.security import hash_password; print(hash_password('import-verify-password'))")
printf "INSERT INTO tenants (id, name, created_at) VALUES (gen_random_uuid(), 'Import Verification Workspace', now()) ON CONFLICT (name) DO NOTHING;\n" \
  "INSERT INTO users (id, tenant_id, email, password_hash, is_active, created_at) SELECT gen_random_uuid(), id, 'import-verify@example.test', :'hash', true, now() FROM tenants WHERE name='Import Verification Workspace' ON CONFLICT DO NOTHING;\n" > /tmp/import_verify_user.sql
sudo docker compose -f ../docker-compose.yml -f ../docker-compose.dev.yml exec -T db \
  psql -U datadesigner -d datadesigner -v hash="$HASH" < /tmp/import_verify_user.sql
```

Then run the verification against the running stack:

```sh
api/.venv/bin/python fixtures/architecture-import/verify_import_flow.py
```

It prints one line per step: preview and match cascade, create/update/skip
counts, information-object alias resolution, integration endpoint resolution
(including the existing-contract update and the blocked row), solution
membership over canonical systems, idempotent re-import, selection-only Current
enrichment, persistence after refresh, and batch-scoped undo with the guarded
conflict path.
